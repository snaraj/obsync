# Self Hosted Private Sync

[Obsidian](https://obsidian.md) のための、自己ホスト型でエンドツーエンド暗号化されたライブ同期です。ダッシュボードを内蔵した依存関係のない Rust 製サーバーを一つ自分で動かし、そこにこのプラグインを組み合わせます。どんなサイズのファイルも扱え、Obsidian のすべてのプラットフォームに対応し、サブスクリプションも第三者もありません。

設定 → コミュニティプラグイン → 閲覧 から **Self Hosted Private Sync**（プラグイン ID `obsync-private-sync`）としてインストールします。Obsidian 1.13.0 以降が必要です。

> [!IMPORTANT]
> このプラグインは、**あなた自身**が動かすサーバーと同期します。ホスティングされたサービスはなく、自分以外の誰かのアカウントもありません。HTTPS で到達できる自分の `obsyncd` がなければ、プラグインには同期する相手がありません。

> [!IMPORTANT]
> 最初の同期の前に保管庫をバックアップし、24 語のリカバリーフレーズは、それを生成したデバイス以外の場所に保管してください。サーバーは暗号文しか保存せず、あなたの代わりに保管庫を復元することはできません。

> [!IMPORTANT]
> 同じ保管庫で、このプラグインを別の同期手段と並べて動かさないでください。Obsidian Sync、ファイルを同期するクラウドフォルダー、ほかの同期プラグインのことです。一つの保管庫を二つの書き手が書き換えると、どちらにも解消できない競合が生まれます。

## 頼りにする前に

これは、あなたのノートの唯一のコピーを同期する、生まれて間もないソフトウェアです。

- **[`CHANGELOG.md`](../../CHANGELOG.md) が、分かっていることの管理されたリストです。** 自分が使っているバージョンの項目と、それより上の項目を読んでください。リリースページは公開時のノートをそのまま保ちます。後から分かったことはこちらに追記されます。
- **保管庫を同期しているすべてのデバイスを更新してください。** 古いバージョンのまま残った一台が、いまだに古い挙動で動作し、ほかのデバイスに影響を与えることがあります。
- **実機で実際に試されたこと**は、実行ごとに [`docs/validation-runs/`](../validation-runs/) に記録されています。各回がカバーしなかったことも含まれます。どの実行でも名前の挙がらないプラットフォームは、実証されていません。
- **「merged concurrent edits」という通知が次々に出る場合**、一つのノートを二台のデバイスで編集しています。片方で Obsidian を終了してもう片方が処理を終えられるようにし、両方を更新してから再開してください。

## このプラグインがアクセスするもの

インストールする前に判断できるよう、短く、そして漏れなく挙げます。

- **ネットワークの宛先は一つ、自分のサーバーだけ。** すべてのリクエストは、プラグインの設定に入力した **Server URL** に送られ、それ以外には一切送られません。テレメトリーも、アナリティクスも、クラッシュレポーターも、広告もなく、同期経路のどこにも第三者のサービスはありません。プラグインがそのサーバーからコードをダウンロードしたり実行したりすることもありません。
- **そのサーバー上のアカウント。作るのはあなたです。** 最初のデバイスは、サーバーが初回起動時に書き出したセットアップトークンを使います。それ以外のデバイスは、すでに同期しているデバイスからペアリングします。Obsidian のアカウントは一切関係しません。
- **Obsidian と GitHub。インストールと更新のときだけ。** `main.js`、`manifest.json`、`styles.css` をこのリポジトリの GitHub Releases からダウンロードするのは Obsidian 自身です。各リリースには、サーバーを配備する人のためのプラグイン ZIP とリリースマニフェストも含まれますが、Obsidian はどちらも無視します。
- **自分のエッジ。設定した場合にだけ。** **Edge service-token headers** に貼り付けたヘッダーは、上記の Server URL への全リクエストに同乗します。それを必要とするプロキシが、あなたのサーバーへの経路上にいるからです。
- **保管庫のファイル一覧。** プラグインは、何が対象範囲かを判断するために保管庫内のすべてのファイルを列挙し、選択したフォルダーの中のファイルを読み、ほかのデバイスが変更した内容を書き込みます。隠しフォルダー（`.obsidian`、`.git`）とシンボリックリンクのフォルダーは対象外です。
- **クリップボード。書き込むだけで、決して読みません。** 書き込むのは **Pair a new device** の **Copy code** と **Copy link** のボタンだけです。プラグインの中にクリップボードを読むものはありません。
- **ブラウザー。ダッシュボードを求めたときに。** **Open dashboard** はサインイン用のリンクをブラウザーで開きます。しかも、そのリンクが自分のサーバー自身のオリジン上にあるときだけです。
- **Obsidian のシークレットストレージ。** 保管庫キー、デバイスシークレット、エッジヘッダーの値はそこに置かれ、平文のプラグインデータに置かれることはありません。

サーバーに何が見え、何が見えないかは [`SECURITY.md`](../../SECURITY.md) と [`docs/threat-model.md`](../threat-model.md) にあります。

## 五つのステップで同期する

このリリースが検証された道筋です。空の保管庫から、二台のデバイスが同期している状態までを辿ります。五つとも、自分のサーバーがすでに動いていることを前提にしています。それは下の節の内容です。各ステップはクイックスタートに全文が書かれています。

1. **コミュニティプラグインからインストールする。** 設定 → コミュニティプラグイン → 閲覧 で **Self Hosted Private Sync** を検索し、インストール、続いて有効化を選びます。ほかのすべての Obsidian プラグインと同じ届き方で、どのプラットフォームでも同じです。

   ![Self Hosted Private Sync とそのインストールボタンを表示している Obsidian のコミュニティプラグインの閲覧画面](../captures/01-install-from-directory.png)

2. **自分のサーバーを指定して設定する。** プラグインの設定タブを開き、**Server URL** を自分のサーバーに設定し、このデバイスが同期するフォルダーを選び、それからセットアップトークンを **First-time setup** の下に貼り付けます。

   ![フォルダー選択、Pairing、First-time setup のトークン入力欄までスクロールしたプラグインの設定タブ](../captures/02-first-time-setup.png)

3. **リカバリーフレーズを保管する。** セットアップはこのデバイス上で保管庫キーを生成し、24 語のフレーズを一度だけ表示します。書き留めて、このデバイス以外の場所に保管してください。サーバーは暗号文しか持たず、あなたの代わりに保管庫を復元することはできないからです。

   ![初回セットアップのあとに表示されるリカバリーフレーズのダイアログ。語は伏せられている](../captures/03-recovery-phrase.png)

4. **二台目のデバイスをワンタイムコードでペアリングする。** 一台目で **Pair a new device** を実行し、表示されたコードを 10 分以内に二台目へ入力し、デバイスを名前で承認します。保管庫キーは、サーバーが決して見ないペアリング用のシークレットで暗号化されて渡ります。

   ![一台目のデバイスの Pair a new device ダイアログ。ワンタイムコードは伏せられている](../captures/04-pair-a-new-device.png)

5. **どちらのデバイスでも編集して、届くのを見る。** 片方のデバイスでノートに入力すると、数秒のうちにもう片方に現れます。双方向で、ステータスバーが同期の状況を示します。

   ![両方のデバイスの編集が入った使い捨てのノートと、見えている同期のステータスバー](../captures/05-sync-both-ways.png)

ダッシュボードのデバイス一覧と、その失効ボタンについては[デバイスを見る](../daily-use.md#see-your-devices)で説明しています。これらは [docs/validation-runs/2026-09-14.md](../validation-runs/2026-09-14.md) に記録された 1.0.0 のデバイス実行では試されていません。

## 同期を始める

最短で正しい道筋はこうです。自分が所有するマシン一台がサーバーを動かし、すべてのデバイスが HTTPS でそこに到達し、各デバイスを一度ずつペアリングします。Obsidian にサインインしても、ここでは何の権限も与えられません。アカウントは自分のサーバー上のものだけです。

### 1. サーバーを起動する

起動のしかたは二通りあります。どちらも、公開者が署名したバイト列をそのまま実行します。署名を検証し、検証された出力からダイジェストを読み取り、そのダイジェストを実行してください。`v1.0.6` はこのページを書いた時点のリリースです。自分がインストールするリリースのタグを使ってください。

```sh
cosign verify ghcr.io/snaraj/obsync:v1.0.6 \
  --certificate-identity https://github.com/snaraj/obsync/.github/workflows/release-publisher.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

**まだ HTTPS がない場合。** `deploy/compose` は、サーバーを自前の TLS 終端（Caddy）の背後で起動します。どのネットワークでも、ドメインなしで、どこのアカウントもなしで動きます。このリポジトリのチェックアウトから実行します。

```sh
OBSYNC_IMAGE=ghcr.io/snaraj/obsync@sha256:<digest> \
  OBSYNC_HOST=sync.example.org \
  OBSYNC_BIND_ADDRESS=192.168.1.10 \
  docker compose -f deploy/compose/docker-compose.yml up -d
```

`OBSYNC_HOST` は、デバイスに入力する名前です。自分のネットワーク内で解決できればそれで十分です。`OBSYNC_BIND_ADDRESS` は、ポート 80 と 443 を公開するこのホストのアドレスです。バインドアドレスが制限するのは宛先のインターフェースであって送信元ではないので、誰が到達できるかを決めるのはファイアウォールです。選ぶまで Compose は起動しません。どちらも[サーバーを動かす](../server.md)で説明しています。

**すでにマシンの前に HTTPS がある場合。** 信頼しているリバースプロキシやトンネルによるものです。その場合は素のサーバーを動かします。ポート 8080 で平文の HTTP を話し、あなたの終端がそこへ転送します。

```sh
docker volume create obsync-blobs
docker volume create obsync-journal
docker run -d --name obsync -p 127.0.0.1:8080:8080 \
  -v obsync-blobs:/data/blobs -v obsync-journal:/data/journal \
  -e OBSYNC_BLOBS_CAPACITY=250GiB -e OBSYNC_JOURNAL_CAPACITY=4GiB \
  -e OBSYNC_PUBLIC_URL=https://sync.example.org \
  ghcr.io/snaraj/obsync@sha256:<the digest cosign just verified>
```

### 2. セットアップトークンを読む

初回起動時に、サーバーはセットアップトークンを発行し、ジャーナルのボリュームにモード 0600 で書き出します。ログには決して出ません。このトークンはアカウントを一度だけ作り、その後もサーバーが生きているあいだずっと、ダッシュボードの復旧用サインインであり続けます。リカバリーフレーズと同じだけの注意を払って扱ってください。補助イメージを使わず、コンテナ自身から読み出します。Compose の場合：

```sh
docker cp obsync-obsync-1:/data/journal/v1/setup-token - | tar -xO
```

素のサーバーの場合：

```sh
docker cp obsync:/data/journal/v1/setup-token - | tar -xO
```

### 3. 証明書を信頼する。デバイスごとに一度（Compose の場合）

Caddy は、初回起動時に自分で生成した認証局からこの証明書を発行しています。そのため、各デバイスにその認証局を信頼するよう一度だけ伝える必要があります。ルート証明書を書き出します。

```sh
docker cp obsync-caddy-1:/data/caddy/pki/authorities/local/root.crt - | tar -xO > obsync-root.crt
```

各デバイスに `obsync-root.crt` をインストールします。macOS、Windows、Linux、iOS、Android それぞれの手順は[認証局を信頼する。デバイスごとに一度](../server.md#trust-the-certificate-authority-once-per-device)にあります。iOS では、証明書を信頼することは、インストールしたあとの二つ目のスイッチです。

### 4. 一台目のデバイスを設定する

1. 設定 → コミュニティプラグイン → 閲覧 → **Self Hosted Private Sync** → インストール → 有効化。
2. プラグインの設定で、**Server URL** を自分のサーバーに設定します。443 以外のポートならポートも含めます：`https://sync.example.org`。

   ![プラグインの設定タブ。デモ用のホスト名が入った Server URL 欄、エッジヘッダーの入力欄、Check と Open dashboard のボタンがある Connection の行](../assets/settings-server.png)

3. いま **Whole vault** か **Selected folders only** を選びます。一度同期したデバイスの選択は、狭める方向にしか変えられません。
4. セットアップトークンを **First-time setup** の下に貼り付け、**Set up** を選びます。24 語のリカバリーフレーズを書き留め、このデバイスには置かないでください。

   ![設定タブの This device セクション。Pair this device と Pair a new device がある Pairing の行、Setup token 欄と Set up ボタンがある First-time setup の行、そして Vault key の行](../assets/settings-setup.png)

### 5. 二台目のデバイスをペアリングする

1. そちらでもプラグインをインストールして有効化し、同じ **Server URL** を設定し、フォルダーを選びます。
2. 一台目で **Pair a new device** を実行します。10 分間有効なコードが表示されます。

   ![一台目のデバイスの Pair a new device ダイアログ。コードは伏せられ、Copy code と Copy link のボタン、そして Waiting for the new device の行がある](../assets/pair-new-device.png)

3. 二台目で **Pair this device** を開き、コードを貼り付けて **Pair** を選びます。

   ![二台目のデバイスの Pair this device ダイアログ。Pairing code 欄は空で、Pair ボタンがある](../assets/pair-this-device.png)

4. 一台目に戻り、新しいデバイスを名前で承認します。どちらかでノートを編集すると、数秒のうちにもう片方に現れます。

   ![新しいデバイスを名前で承認するかどうかを尋ねている一台目のデバイス。Approve と Reject のボタンがある](../assets/pair-approve.png)

   ![一台目で書かれたノートを表示している二台目のデバイス。ステータスバーには obsync idle と出ている](../assets/first-sync.png)

ペアリングのやり取り全体を、短いループ一つにまとめたものです。

![アニメーション：一台目に表示されたペアリングコードが二台目に貼り付けられ、一台目で承認され、最初のノートが二台目に届くまで](../assets/pairing.gif)

スマートフォンのスクリーンショットは、まだこのリポジトリにはありません。メンテナー自身のデバイスで撮影され、検証実行がそれを記録した時点で追加されます。

各画面が何を求め、それがなぜなのかも含めた全ステップは[クイックスタート](../quickstart.md)にあります。

**一台のコンピューターで試す場合。** コンピューターでは、プラグインは平文の `http://` アドレスも受け付けるので、`http://127.0.0.1:8080` で終端なしに上記の素のサーバーへ届きます。スマートフォンでは違います。iOS と Android の Obsidian は平文の HTTP を拒否します。

## 応用：Cloudflare

リファレンス構成には**公開ホスト名がありません**。Cloudflare Tunnel がサーバーのプライベートネットワークを Cloudflare につなぎ、プライベートルートがどのアドレスがそのトンネルの背後にあるかを Cloudflare に伝え、各デバイスの Cloudflare One クライアントが Server URL への通信をそこへ運びます。インターネットから到達できるものは何もなく、大きな初回同期が公開ホスト名を経由することもありません。もう一つの構成、つまり **Edge service-token headers** にサービストークンを入れ、サーバーで `OBSYNC_EDGE=cloudflare` を設定した、Cloudflare Access の背後の公開ホスト名もサポートしています。どちらも手順を追って説明しています：[Cloudflare](cloudflare.md)。

## サーバーに届くほかの方法

一つにつき一行、手順の説明はしません。何を選ぶにしても、プラグインにはすべてのデバイスが信頼する証明書を備えた HTTPS が必要で、サーバー自身はその終端の背後で平文の HTTP のままです。

- **LAN だけ。** 上記の Compose の構成を、自宅でだけ使います。いちばん簡単ですが、外出先での同期はできません。
- **WireGuard。** 自分のネットワークへ戻る自前の VPN です。最も速く、完全に自分のものですが、すべてのデバイスにピア設定を持ち歩き、エンドポイントを一つ到達可能に保つ必要があります。
- **Tailscale。** 独自の名前を持つ、管理された WireGuard のメッシュです。デバイス側の設定は最小で済みますが、メッシュを調整するのは第三者であり、そのプランの上限は自分で読む必要があります。
- **自動 TLS 付きのリバースプロキシ。** 公開の名前で動く Caddy などです。公開的に信頼された証明書と恒久的なアドレスが手に入りますが、サーバーはインターネットから到達可能になり、プロキシとその更新を正しく保つのは自分の責任です。
- **Cloudflare Tunnel。** 上記のとおりです。受信ポートは不要ですが、経路上に独自の条件を持つプロバイダーがいます。

どれを選んだ場合でも、外出先のデバイスに必要なもの（経路、名前、証明書、iOS のローカルネットワークの確認、ファイアウォール）は[LAN の外から到達する](../server.md#reaching-it-from-outside-your-lan)にあります。

## トラブルシューティング

| 症状 | 考えられる原因 | まず試すこと |
| --- | --- | --- |
| `obsync: offline` | デバイスが Server URL に到達できない | 同じデバイスのブラウザーでその URL を開き、ポート、HTTPS、経路を確認する |
| コンピューターは同期しているのに、スマートフォンがつながらない | スマートフォンでプライベート証明書が信頼されていない | ルート証明書をインストールする。iOS ではさらに「証明書信頼設定」でオンにする |
| `401 stale_timestamp` | どこかの時計が 300 秒以上ずれている | デバイスかサーバーで、時刻の自動設定をオンにする |
| `403 device_pending` | まだ誰もそのデバイスを承認していない | ペアリング元のデバイスで、名前を見て承認する |
| ファイルがいつまでも届かない | フォルダー選択の外にあるか、スマートフォンのサイズ上限を超えている | **Sync folders on this device** を確認する。スマートフォンでは **Show remote-only files** を実行する |

それ以外のすべての症状、すべてのエラーコード、そして送る価値のあるレポートの集め方は[トラブルシューティング](../troubleshooting.md)にあります。

## 質問、バグ、セキュリティ

- **質問、あるいはバグかどうか自信がないこと：**
  [Discussions](https://github.com/snaraj/obsync/discussions)。
- **バグ：** バグ報告テンプレートと、[トラブルシューティング](../troubleshooting.md)に書かれているレポートを添えて、[イシューを作成してください](https://github.com/snaraj/obsync/issues/new/choose)。トークン、リカバリーフレーズ、公開したくないアドレスは含めないでください。
- **脆弱性の疑い：** 公開のイシューにはせず、[`SECURITY.md`](../../SECURITY.md) を通じて非公開で報告してください。
