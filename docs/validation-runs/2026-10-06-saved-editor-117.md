# Saved-editor candidate, 2026-10-06

This candidate separates recent-input attribution, confirmed native saving,
publication batching and incoming-write safety. It is not yet accepted on the
physical phone or the complete desktop/mobile platform matrix. The preceding
Windows and Android records test older plugin bytes.

## Reproduction and scope

The local native experiments used macOS 27.0 (26A428), arm64, Obsidian 1.13.4,
two fresh native profiles and synthetic vaults. The server and plugin retained
end-to-end encryption, authenticated requests and durable writes. Transport
was loopback HTTP; these observations do not establish TLS latency. Desktop
profiles used the explicit mock-keychain testing mode, so they do not establish
native credential custody.

The experimental launcher takes an explicit built source and a new external
run directory:

```sh
OBSYNC_LATENCY_CADENCE_MS=50 OBSYNC_LATENCY_CHARACTERS=180 \
  python3 -B experiments/sync-117/test.py latency --source "$SOURCE" --run "$RUN"
```

The control used `100` and `120`, respectively. The experimental harness is
separate from shipped code. Both run receipts retain the driver hash. Each
scenario places each caret once, uses trusted native input, reads complete
editor and filesystem bytes independently, checks every character and final
cursor, waits for idle, observes two further seconds of stable content, checks
one server head and refuses extra conflict copies.

## Individual native observations

These are two individual runs, not a paired statistical speedup claim.
Visibility was sampled at approximately 100 ms and is an observation bound,
not a paint or network timestamp. Event-based repeated comparisons follow
separately under #325's measurement requirements.

| Run / cadence | Scenario | Settling after final input | Maximum observed remote visibility |
| --- | --- | ---: | ---: |
| snapshot-preparation / 50 ms | one way | 78 ms | 274 ms |
| snapshot-preparation / 50 ms | short two way | 445 ms | 649 ms |
| snapshot-preparation / 50 ms | continuous, 180 characters each | 418 ms | 1,410 ms |
| snapshot-preparation-control / 100 ms | one way | 257 ms | 255 ms |
| snapshot-preparation-control / 100 ms | short two way | 434 ms | 530 ms |
| snapshot-preparation-control / 100 ms | continuous, 120 characters each | 486 ms | 923 ms |

All six scenarios met the existing 1,500 ms observation budget. Both continuous
scenarios showed remote edits during input, retained exact final bytes and
cursors, produced no conflict copies and created no new notices on either
peer. The during-input and settled continuous screenshots from both peers in
both runs were opened and inspected: matching final text, visible cursors,
clear editors and settled sync indicators. No CSS or notice setting hid errors.
The initial short scenarios showed at most two notices together and no native
external-modification warning.

Earlier experiments remain failures: a saved-baseline lease lost a character;
an initial queued refresh fell back to the ten-second wait; a durable-save
trial produced a spurious conflict copy after exhausting recursive history;
and the publication-batch trial missed the visibility budget at 1,536 ms.
The current code confirms the actual bridged text, flushes the subsequent
native save, reuses locally verified parent merges within the existing memory
and recursion limits, and allows preparation from a proven saved snapshot
while retaining final current-editor checks. None of the failed results is
upgraded by a later pass.

## Local gate and mutation evidence

`make check` passed on the current source: 2,055/2,055 plugin tests, 83/83
dashboard tests, 873 repository contracts, CLI and chart checks, 94.72% Rust
line coverage, and redacted working-tree and outgoing-range secret scans.
The first full attempt had two test-assumption failures: a permissive-host
scenario no longer reliably received a write while unsaved, and a depth test
mistook the new refusal diagnostic for an actual fourth-level traversal.
The scenario now deliberately waits for pending input; byte, copy, head and
status assertions remain. The depth test distinguishes refusal from traversal.
The focused reproduction passed 3/3 before the complete gate passed.

Twenty-four deliberate compiled-code mutations were detected; the runner
restored all files afterward. They cover save/readback and input generation,
size and pane agreement, refresh/composition/binding, historical snapshot
content and lifetime, expected incoming bytes, queue ownership, public saving,
final fsync, capture consistency, growing-file refusal, stopped/advanced merge
parents, dirty local deltas, pure network merges, verified-parent reuse, the
first-save batch deadline and saved-snapshot preparation. These are author
checks, not an independent review verdict.

Both completed native controllers proved zero owned process groups and no
remaining private directory, runtime or live manifest. Only reduced evidence
and synthetic captures were retained. The launcher additionally now checks
loopback binding before artifact copying and records ownership before copying;
injected copy failure exercises cleanup. Physical-phone acceptance remains
pending: the latest Mirroring check required Mac authentication. No credential
was entered and no new phone fixture was installed in these runs.
