Observed 2026-10-05. This is validation evidence, not a release or a claim that
all of #325 is complete. Reference-server component stages are measured below. Physical-phone
acceptance remains unperformed. The isolated desktop profiles use the installed
Obsidian 1.13.4 application and a disposable mock keychain; they do not prove
personal OS keychain custody. No personal vault or production account is used.

## Two native windows

The released baseline paired through setup/recovery confirmation and matching
codes. A-to-B transfer took 1,077 ms and B-to-A 1,029 ms in this functional
rehearsal. Both independent disk reads, editor text and nonempty file identities
agreed. Restart returned A/B to idle in 1,447/1,428 ms without re-pairing.
The interface sweep observed zero console errors, warnings or exceptions.
These are single observations, not latency distributions or before/after gains.

Reproduce with `python3 "$EXPERIMENT/test.py" desktop --source "$BASELINE"
--run "$RUN"`. The peer editor, idle status and folder/pair settings captures
were visually inspected: all 18 captures are recorded in a separate inspection
receipt. Input values were masked for capture. Screenshots alone are not the byte oracle.

## Stage split with protections enabled (#325)

Three fresh component passes per platform use the compiled plugin crypto and
chunking primitives under pinned Node 26.10.0, 128 synthetic notes of roughly
8 KiB, a deterministic 32 MiB plus one byte binary, and an unchanged-fixture reread/chunk/hash measurement. The client validates a task-local TLS certificate and hostname;
no host trust store changes. HMAC authentication, nonce persistence, encrypted
manifests/chunks, integrity verification and all file/directory/journal flushes
remain enabled. The same process downloads and decrypts chunks using its
in-memory descriptors, then independently reads the output file. This does not
exercise a second device or retrieval/decryption of the stored manifest. The component run is **not native Obsidian** or a network-route benchmark.

The ARM run uses two allowed CPUs, lower scheduling priority, a 600-second
wall budget, and sampled abort thresholds of 1 GiB child-process RSS, 2 GiB
scratch and 4 GiB free space. Polling permits transient overshoot; RSS excludes
the Python launcher and TLS proxy. Host idleness is not proven. The desktop and ARM results must not be read
as a CPU comparison: filesystem flush behavior and their operating systems differ.

Reproduction: the measurement-only branch preserves the exact original hook
recipe and all four before/after source hashes under
`experiments/sync-117/provenance/`. Its maintained hooks subsequently gained a
Rust formatting correction and a guarded renderer-window lookup to satisfy

The native client uses ordinary upload concurrency and a 200 ms completion poll;
the small Sync now wall observations are consequently quantized. Unlike the component
reread/chunk/hash measurement, this path does not reread the large unchanged file. Runs two
and three require acknowledged nonempty version IDs in both live and persisted
state. Independent originating-vault readback checks file length and persisted
state, and records its digest; it does not compare remote bytes. A scan of server
storage finds none of the selected plaintext sentinels. Instrumented plugin SHA-256:
`20658b177a4c887610ad196c5c80f9f1efb757bbdd636511db9d3828ea3a03ba`.
Instrumentation overhead against a matching uninstrumented workload remains
unmeasured; these figures locate costs, not a proven shipping improvement.

The evidence supports investigating request and durable-write overhead first.
Upload pipelining, multi-note download prefetch, and nonce/journal group commit
already exist. They must not be reported as newly implemented. A metadata-only
Sync now cache was rejected before publication: timestamp representation cannot
prove filesystem change-clock resolution, so a same-size edit could be missed.
The candidate retains content verification. Independent apply concurrency also
needs path-conflict reservations, per-worker staging and ordered durable cursor
advancement; changing the serial loop alone is unsafe. Small-note upload batching
requires the protocol skew, blind-server and mixed-version gates in #325. No
performance lever or co-editing engine is declared delivered by this report.

## Cleanup and acceptance boundary

Every completed native sample has zero owned groups/holders and no runtime.
Resolved profiles, account keys, private logs, task certificates, synthetic notes
and server history are removed; only reduced evidence and screenshots remain.
Two native teardown first attempts failed and are recorded separately: a holder
exit without its receipt, and a macOS process-exit/signal race. Independent
identity/absence checks completed cleanup; later automatic teardown succeeded.
The ARM scratch and its staged inputs were removed, then the exact temporary
privilege grant was revoked and the worker transport closed.

Physical-phone, Android and Windows/Linux sync acceptance are not supplied by
these desktop or component measurements. This document does not close #325 or
claim release readiness.
