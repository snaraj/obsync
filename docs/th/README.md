# Self Hosted Private Sync

การซิงก์สดแบบโฮสต์เอง เข้ารหัสจากต้นทางถึงปลายทาง สำหรับ [Obsidian](https://obsidian.md): เซิร์ฟเวอร์ Rust ตัวเดียวที่ไม่ต้องพึ่งดีเพนเดนซีใด ๆ พร้อมแดชบอร์ดในตัว ซึ่งคุณรันเอง บวกกับปลั๊กอินตัวนี้ ไฟล์ขนาดใดก็ได้ ทุกแพลตฟอร์มของ Obsidian ไม่มีการสมัครสมาชิก ไม่มีบุคคลที่สาม

ติดตั้งจาก การตั้งค่า → ปลั๊กอินโดยชุมชน → เลือกดู โดยค้นหาชื่อ **Self Hosted Private Sync** (ไอดีปลั๊กอิน `obsync-private-sync`) บน Obsidian 1.13.0 ขึ้นไป

> [!IMPORTANT]
> ปลั๊กอินนี้ซิงก์ไปยังเซิร์ฟเวอร์ที่ **คุณ** รันเอง ไม่มีบริการแบบโฮสต์ให้ และไม่มีบัญชีกับใครนอกจากตัวคุณเอง: หากไม่มี `obsyncd` ของคุณเองที่เข้าถึงได้ผ่าน HTTPS ปลั๊กอินก็ไม่มีอะไรให้ซิงก์ด้วย

> [!IMPORTANT]
> สำรองข้อมูลห้องนิรภัยของคุณก่อนการซิงก์ครั้งแรก และเก็บวลีกู้คืน 24 คำไว้ที่อื่นที่ไม่ใช่อุปกรณ์ที่สร้างมันขึ้นมา เซิร์ฟเวอร์เก็บไว้แต่ข้อมูลที่เข้ารหัสแล้วเท่านั้น และไม่สามารถกู้คืนห้องนิรภัยให้คุณได้

> [!IMPORTANT]
> อย่ารันปลั๊กอินนี้ควบคู่กับโซลูชันซิงก์อื่นบนห้องนิรภัยเดียวกัน — ไม่ว่าจะเป็น Obsidian Sync โฟลเดอร์คลาวด์ที่ซิงก์ไฟล์ หรือปลั๊กอินซิงก์ตัวอื่น ผู้เขียนสองรายบนห้องนิรภัยเดียวกันย่อมสร้างความขัดแย้งที่ไม่มีฝ่ายใดแก้ให้ลงรอยกันได้

## ก่อนที่คุณจะไว้วางใจมัน

นี่คือซอฟต์แวร์ที่ยังใหม่ และมันซิงก์สำเนาเพียงชุดเดียวที่คุณมีของโน้ตทั้งหมด

- **[`CHANGELOG.md`](../../CHANGELOG.md) คือรายการที่ดูแลปรับปรุงไว้เสมอว่ามีอะไรที่รู้แล้วบ้าง** อ่านรายการของเวอร์ชันที่คุณใช้อยู่ และรายการทั้งหมดที่อยู่เหนือขึ้นไป หน้าเผยแพร่รุ่นจะคงบันทึกที่เผยแพร่ไปพร้อมกันไว้อย่างนั้น ส่วนสิ่งที่ค้นพบภายหลังจะถูกเพิ่มไว้ที่นี่
- **อัปเดตอุปกรณ์ทุกเครื่องที่ซิงก์ห้องนิรภัย** อุปกรณ์เพียงเครื่องเดียวที่ยังค้างอยู่บนเวอร์ชันเก่าก็ยังทำงานตามพฤติกรรมเดิมได้ และส่งผลถึงเครื่องอื่น ๆ
- **สิ่งที่ถูกทดสอบจริงบนฮาร์ดแวร์** ถูกบันทึกไว้เป็นรายครั้งใน [`docs/validation-runs/`](../validation-runs/) รวมถึงสิ่งที่การทดสอบแต่ละครั้งไม่ได้ครอบคลุม แพลตฟอร์มที่ไม่มีการทดสอบครั้งใดเอ่ยถึง คือแพลตฟอร์มที่ยังไม่ได้รับการพิสูจน์
- **สายธารของข้อความแจ้ง "merged concurrent edits"** บนอุปกรณ์สองเครื่องที่กำลังแก้ไขโน้ตเดียวกัน: ให้ปิด Obsidian บนเครื่องหนึ่ง เพื่อให้อีกเครื่องทำงานที่ค้างอยู่จนหมด อัปเดตทั้งสองเครื่อง แล้วจึงทำงานต่อ

## สิ่งที่ปลั๊กอินนี้เข้าถึง

สั้นและครบถ้วน เพื่อให้คุณตัดสินใจได้ก่อนติดตั้ง

- **ปลายทางเครือข่ายเพียงแห่งเดียว: เซิร์ฟเวอร์ของคุณเอง** ทุกคำขอไปยัง **Server URL** ที่คุณพิมพ์ลงในการตั้งค่าของปลั๊กอิน และไม่ไปที่อื่นเลย ไม่มีเทเลเมทรี ไม่มีการวิเคราะห์การใช้งาน ไม่มีตัวรายงานการแครช ไม่มีโฆษณา และไม่มีบริการของบุคคลที่สามอยู่ที่ใดเลยบนเส้นทางการซิงก์ ทั้งปลั๊กอินก็ไม่เคยดาวน์โหลดหรือรันโค้ดจากเซิร์ฟเวอร์นั้นเช่นกัน
- **บัญชีบนเซิร์ฟเวอร์นั้น ซึ่งคุณสร้างขึ้นเอง** อุปกรณ์เครื่องแรกใช้โทเค็นตั้งค่าที่เซิร์ฟเวอร์ของคุณเขียนไว้ตอนบูตครั้งแรก ส่วนอุปกรณ์เครื่องอื่นทุกเครื่องจะจับคู่จากอุปกรณ์ที่ซิงก์อยู่แล้ว บัญชี Obsidian ของคุณไม่มีส่วนเกี่ยวข้องใด ๆ
- **Obsidian และ GitHub สำหรับการติดตั้งและการอัปเดตเท่านั้น** Obsidian เองเป็นผู้ดาวน์โหลด `main.js`, `manifest.json` และ `styles.css` จาก GitHub Releases ของรีโพซิทอรีนี้ แต่ละ Release ยังมีไฟล์ ZIP ของปลั๊กอินและ manifest ของรุ่นสำหรับคนที่นำเซิร์ฟเวอร์ไปติดตั้งด้วย ซึ่ง Obsidian ไม่สนใจทั้งสองอย่าง
- **edge ของคุณ เฉพาะเมื่อคุณตั้งค่าไว้เท่านั้น** ส่วนหัวที่คุณวางไว้ใต้ **Edge service-token headers** จะเดินทางไปพร้อมกับทุกคำขอที่ส่งไปยัง Server URL ข้างต้น เพราะพร็อกซีที่ต้องใช้มันอยู่บนเส้นทางไปยังเซิร์ฟเวอร์ของคุณ
- **รายการไฟล์ในห้องนิรภัยของคุณ** ปลั๊กอินจะไล่รายการไฟล์ทุกไฟล์ในห้องนิรภัยเพื่อตัดสินว่าอะไรอยู่ในขอบเขต อ่านไฟล์ที่อยู่ในโฟลเดอร์ที่คุณเลือกไว้ และเขียนสิ่งที่อุปกรณ์เครื่องอื่นเปลี่ยนแปลง โฟลเดอร์ที่ซ่อนไว้ (`.obsidian`, `.git`) และโฟลเดอร์ที่เป็นซิมลิงก์จะถูกข้ามไป
- **คลิปบอร์ด ซึ่งถูกเขียนแต่ไม่เคยถูกอ่าน** มีเพียงปุ่ม **Copy code** และ **Copy link** ใน **Pair a new device** เท่านั้นที่เขียนลงไป ไม่มีส่วนใดในปลั๊กอินที่อ่านคลิปบอร์ด
- **เบราว์เซอร์ของคุณ เมื่อคุณเรียกใช้แดชบอร์ด** **Open dashboard** จะเปิดลิงก์เข้าสู่ระบบในเบราว์เซอร์ของคุณ และจะทำก็ต่อเมื่อลิงก์นั้นอยู่บนออริจินของเซิร์ฟเวอร์ของคุณเองเท่านั้น
- **ที่เก็บความลับของ Obsidian** กุญแจห้องนิรภัย ความลับของอุปกรณ์ และค่าส่วนหัวของ edge ใด ๆ อยู่ที่นั่น ไม่เคยอยู่ในข้อมูลปลั๊กอินแบบธรรมดา

สิ่งที่เซิร์ฟเวอร์มองเห็นได้และมองไม่เห็นนั้นอยู่ใน [`SECURITY.md`](../../SECURITY.md) และ [`docs/threat-model.md`](../threat-model.md)

## ซิงก์ให้สำเร็จในห้าขั้นตอน

เส้นทางที่รุ่นนี้ผ่านการทดสอบมา ตั้งแต่ห้องนิรภัยที่ว่างเปล่าไปจนถึงอุปกรณ์สองเครื่องที่ซิงก์ตรงกัน ทั้งห้าขั้นตอนตั้งอยู่บนสมมติฐานว่าเซิร์ฟเวอร์ของคุณเองทำงานอยู่แล้ว ซึ่งเป็นเนื้อหาของหัวข้อถัดไปด้านล่าง และแต่ละขั้นตอนเขียนไว้อย่างครบถ้วนในคู่มือเริ่มต้นอย่างรวดเร็ว

1. **ติดตั้งจากปลั๊กอินโดยชุมชน** ใน การตั้งค่า → ปลั๊กอินโดยชุมชน → เลือกดู ให้ค้นหา **Self Hosted Private Sync** แล้วเลือก ติดตั้ง จากนั้น เปิดใช้งาน — แบบเดียวกับที่ปลั๊กอิน Obsidian ตัวอื่นทุกตัวเข้ามา บนทุกแพลตฟอร์ม

   ![หน้าเลือกดูปลั๊กอินโดยชุมชนของ Obsidian ที่แสดง Self Hosted Private Sync พร้อมปุ่มติดตั้งของมัน](../captures/01-install-from-directory.png)

2. **ชี้ไปที่เซิร์ฟเวอร์ของคุณแล้วตั้งค่ามัน** เปิดแท็บการตั้งค่าของปลั๊กอิน ตั้ง **Server URL** ให้เป็นเซิร์ฟเวอร์ของคุณเอง เลือกว่าอุปกรณ์เครื่องนี้จะซิงก์โฟลเดอร์ใดบ้าง แล้ววางโทเค็นตั้งค่าของคุณใต้ **First-time setup**

   ![แท็บการตั้งค่าของปลั๊กอิน เลื่อนลงมาที่การเลือกโฟลเดอร์ แถว Pairing และช่องโทเค็นใต้ First-time setup](../captures/02-first-time-setup.png)

3. **เก็บวลีกู้คืนไว้ให้ดี** การตั้งค่าจะสร้างกุญแจห้องนิรภัยขึ้นบนอุปกรณ์เครื่องนี้ และแสดงวลี 24 คำให้เห็นเพียงครั้งเดียว: จดมันไว้และเก็บไว้ที่อื่นที่ไม่ใช่อุปกรณ์เครื่องนี้ เพราะเซิร์ฟเวอร์เก็บไว้แต่ข้อมูลที่เข้ารหัสแล้ว และไม่สามารถกู้คืนห้องนิรภัยให้คุณได้

   ![กล่องโต้ตอบวลีกู้คืนที่แสดงขึ้นหลังการตั้งค่าครั้งแรก โดยคำต่าง ๆ ถูกปิดบังไว้](../captures/03-recovery-phrase.png)

4. **จับคู่อุปกรณ์เครื่องที่สองด้วยรหัสใช้ครั้งเดียว** เรียก **Pair a new device** บนอุปกรณ์เครื่องแรก กรอกรหัสที่มันแสดงลงบนเครื่องที่สองภายในสิบนาที แล้วอนุมัติอุปกรณ์นั้นตามชื่อของมัน — กุญแจห้องนิรภัยเดินทางในรูปแบบที่เข้ารหัสไว้ด้วยความลับของการจับคู่ซึ่งเซิร์ฟเวอร์ไม่เคยเห็น

5. **แก้ไขบนเครื่องใดก็ได้ แล้วดูมันไปถึงอีกเครื่อง** พิมพ์ลงในโน้ตบนอุปกรณ์เครื่องหนึ่ง แล้วมันจะไปปรากฏบนอีกเครื่องภายในไม่กี่วินาที ทั้งสองทิศทาง โดยมีแถบสถานะคอยแสดงว่าการซิงก์กำลังทำอะไรอยู่

รายชื่ออุปกรณ์ของแดชบอร์ดและปุ่มเพิกถอนของมันอธิบายไว้ใต้ [ดูอุปกรณ์ของคุณ](../daily-use.md#see-your-devices) และไม่ได้ถูกทดสอบในการทดสอบด้วยอุปกรณ์จริงของรุ่น 1.0.0 ที่บันทึกไว้ใน [docs/validation-runs/2026-09-14.md](../validation-runs/2026-09-14.md)

## เริ่มซิงก์

เส้นทางที่สั้นที่สุดและถูกต้อง: เครื่องหนึ่งที่คุณเป็นเจ้าของรันเซิร์ฟเวอร์ อุปกรณ์ทุกเครื่องเข้าถึงมันผ่าน HTTPS และอุปกรณ์แต่ละเครื่องถูกจับคู่หนึ่งครั้ง การลงชื่อเข้าใช้ Obsidian ไม่ได้ให้สิทธิ์อะไรที่นี่ บัญชีเดียวที่มีคือบัญชีบนเซิร์ฟเวอร์ของคุณ

### 1. เริ่มเซิร์ฟเวอร์

มีสองวิธีในการเริ่มมัน ทั้งสองวิธีรันไบต์ชุดเดียวกับที่ผู้เผยแพร่ลงลายเซ็นไว้ทุกประการ: ตรวจสอบลายเซ็น อ่าน digest จากผลลัพธ์ที่ตรวจสอบแล้ว จากนั้นรัน digest นั้น `v1.0.6` คือรุ่นที่หน้านี้เขียนขึ้นโดยอ้างอิง ให้ใช้แท็กของรุ่นที่คุณกำลังติดตั้ง

```sh
cosign verify ghcr.io/snaraj/obsync:v1.0.6 \
  --certificate-identity https://github.com/snaraj/obsync/.github/workflows/release-publisher.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

**ยังไม่มี HTTPS ใช่ไหม** `deploy/compose` จะเริ่มเซิร์ฟเวอร์ไว้หลังจุดสิ้นสุด TLS ของตัวมันเอง (Caddy) บนเครือข่ายใดก็ได้ โดยไม่ต้องมีโดเมนและไม่ต้องมีบัญชีกับใครทั้งสิ้น จากการเช็กเอาต์รีโพซิทอรีนี้:

```sh
OBSYNC_IMAGE=ghcr.io/snaraj/obsync@sha256:<digest> \
  OBSYNC_HOST=sync.example.org \
  OBSYNC_BIND_ADDRESS=192.168.1.10 \
  docker compose -f deploy/compose/docker-compose.yml up -d
```

`OBSYNC_HOST` คือชื่อที่อุปกรณ์ของคุณจะพิมพ์ มันแค่ต้องแปลงชื่อได้บนเครือข่ายของคุณเองก็พอ ส่วน `OBSYNC_BIND_ADDRESS` คือที่อยู่ของโฮสต์เครื่องนี้ที่พอร์ต 80 และ 443 ถูกเผยแพร่อยู่: ที่อยู่สำหรับ bind จำกัดอินเทอร์เฟซปลายทาง ไม่ใช่ต้นทาง ดังนั้นไฟร์วอลล์ของคุณคือสิ่งที่ตัดสินว่าใครเข้าถึงมันได้ Compose จะไม่ยอมเริ่มทำงานจนกว่าคุณจะเลือก ทั้งสองอย่างอธิบายไว้ใน [การรันเซิร์ฟเวอร์](../server.md)

**มี HTTPS อยู่ด้านหน้าเครื่องนั้นอยู่แล้ว** ไม่ว่าจะจาก reverse proxy หรืออุโมงค์ที่คุณเชื่อถือใช่ไหม ให้รันเซิร์ฟเวอร์เปล่า ๆ มันพูด HTTP ธรรมดาบนพอร์ต 8080 และจุดสิ้นสุด TLS ของคุณจะส่งต่อไปยังมัน:

```sh
docker volume create obsync-blobs
docker volume create obsync-journal
docker run -d --name obsync -p 127.0.0.1:8080:8080 \
  -v obsync-blobs:/data/blobs -v obsync-journal:/data/journal \
  -e OBSYNC_BLOBS_CAPACITY=250GiB -e OBSYNC_JOURNAL_CAPACITY=4GiB \
  -e OBSYNC_PUBLIC_URL=https://sync.example.org \
  ghcr.io/snaraj/obsync@sha256:<the digest cosign just verified>
```

### 2. อ่านโทเค็นตั้งค่า

เมื่อบูตครั้งแรก เซิร์ฟเวอร์จะสร้างโทเค็นตั้งค่าขึ้นมาและเขียนลงบนโวลุ่มเจอร์นัลของมัน โหมด 0600 และไม่เคยถูกบันทึกลงล็อก โทเค็นนี้สร้างบัญชีของคุณหนึ่งครั้ง จากนั้นมันจะยังคงเป็นวิธีเข้าสู่ระบบสำหรับกู้คืนของแดชบอร์ดไปตลอดอายุของเซิร์ฟเวอร์: เก็บรักษามันด้วยความระมัดระวังเท่ากับวลีกู้คืน อ่านมันจากตัวคอนเทนเนอร์เอง โดยไม่ต้องใช้อิมเมจช่วยใด ๆ บนเส้นทาง Compose:

```sh
docker cp obsync-obsync-1:/data/journal/v1/setup-token - | tar -xO
```

บนเส้นทางเซิร์ฟเวอร์เปล่า:

```sh
docker cp obsync:/data/journal/v1/setup-token - | tar -xO
```

### 3. เชื่อถือใบรับรอง หนึ่งครั้งต่ออุปกรณ์หนึ่งเครื่อง (เส้นทาง Compose)

Caddy ออกใบรับรองจากผู้ออกใบรับรองที่มันสร้างขึ้นเองตอนเริ่มทำงานครั้งแรก ดังนั้นต้องบอกอุปกรณ์แต่ละเครื่องให้เชื่อถือผู้ออกใบรับรองนั้นหนึ่งครั้ง ส่งออกใบรับรองราก:

```sh
docker cp obsync-caddy-1:/data/caddy/pki/authorities/local/root.crt - | tar -xO > obsync-root.crt
```

ติดตั้ง `obsync-root.crt` บนอุปกรณ์ทุกเครื่อง ขั้นตอนสำหรับ macOS, Windows, Linux, iOS และ Android อยู่ใน [เชื่อถือผู้ออกใบรับรอง หนึ่งครั้งต่ออุปกรณ์หนึ่งเครื่อง](../server.md#trust-the-certificate-authority-once-per-device) บน iOS การเชื่อถือใบรับรองเป็นสวิตช์ที่สองหลังจากติดตั้งมันแล้ว

   ![แท็บการตั้งค่าของปลั๊กอิน: ช่อง Server URL ที่บรรจุชื่อโฮสต์สำหรับสาธิต กล่องส่วนหัวของ edge และแถว Connection พร้อมปุ่ม Check และ Open dashboard ของมัน](../assets/settings-server.png)

**กำลังลองบนคอมพิวเตอร์เครื่องเดียวอยู่ใช่ไหม** บนคอมพิวเตอร์ ปลั๊กอินยอมรับที่อยู่ `http://` ธรรมดาด้วย ดังนั้น `http://127.0.0.1:8080` จึงเข้าถึงเซิร์ฟเวอร์เปล่าข้างต้นได้โดยไม่ต้องมีจุดสิ้นสุด TLS แต่โทรศัพท์ทำไม่ได้: Obsidian บน iOS และ Android ปฏิเสธ HTTP ธรรมดา

## ขั้นสูง: Cloudflare

การติดตั้งอ้างอิง **ไม่มีชื่อโฮสต์สาธารณะ** Cloudflare Tunnel เชื่อมเครือข่ายส่วนตัวของเซิร์ฟเวอร์เข้ากับ Cloudflare เส้นทางส่วนตัวบอก Cloudflare ว่าที่อยู่ใดอยู่หลังอุโมงค์นั้น และไคลเอนต์ Cloudflare One บนอุปกรณ์แต่ละเครื่องนำ Server URL ไปถึงที่นั่น ไม่มีอะไรเข้าถึงได้จากอินเทอร์เน็ต และการซิงก์ครั้งแรกขนาดใหญ่ก็ไม่ได้ถูกส่งผ่านพร็อกซีของชื่อโฮสต์สาธารณะ ส่วนอีกแบบหนึ่ง คือชื่อโฮสต์สาธารณะที่อยู่หลัง Cloudflare Access พร้อมโทเค็นบริการใน **Edge service-token headers** และ `OBSYNC_EDGE=cloudflare` บนเซิร์ฟเวอร์ ก็รองรับเช่นกัน ทั้งสองแบบ ทีละขั้นตอน: [Cloudflare](cloudflare.md)

## วิธีอื่นในการเข้าถึงเซิร์ฟเวอร์ของคุณ

บรรทัดเดียวต่อหนึ่งวิธี ไม่ใช่บทเรียนสอน ไม่ว่าคุณจะเลือกแบบไหน ปลั๊กอินต้องการ HTTPS พร้อมใบรับรองที่อุปกรณ์ทุกเครื่องเชื่อถือ และตัวเซิร์ฟเวอร์เองยังคงอยู่บน HTTP ธรรมดาหลังจุดสิ้นสุด TLS นั้น

- **LAN เท่านั้น** เส้นทาง Compose ข้างต้น เข้าถึงได้เฉพาะที่บ้าน ง่ายที่สุด แต่ไม่มีการซิงก์เมื่ออยู่นอกบ้าน
- **WireGuard** VPN ของคุณเองที่ย้อนกลับเข้าสู่เครือข่ายของคุณ เร็วที่สุดและเป็นของคุณทั้งหมด คุณต้องพกการตั้งค่าเพียร์ไว้บนอุปกรณ์ทุกเครื่อง และรักษาปลายทางหนึ่งจุดให้เข้าถึงได้เสมอ
- **Tailscale** เมช WireGuard แบบมีผู้ดูแลพร้อมชื่อของตัวเอง ตั้งค่าบนอุปกรณ์น้อยที่สุด แต่มีบุคคลที่สามคอยประสานเมชนั้น และขีดจำกัดของแพ็กเกจก็เป็นเรื่องที่คุณต้องอ่านเอง
- **reverse proxy ที่ทำ TLS อัตโนมัติ** เช่น Caddy บนชื่อสาธารณะ ได้ใบรับรองที่เชื่อถือได้ในระดับสาธารณะและที่อยู่ถาวร แต่เซิร์ฟเวอร์จะเข้าถึงได้จากอินเทอร์เน็ต และพร็อกซีกับการอัปเดตของมันเป็นเรื่องที่คุณต้องดูแลให้ถูกต้องเอง
- **Cloudflare Tunnel** ตามข้างต้น ไม่มีพอร์ตขาเข้า แต่มีผู้ให้บริการอยู่บนเส้นทางพร้อมเงื่อนไขของตัวเอง

สิ่งที่อุปกรณ์ซึ่งเดินทางไปไหนมาไหนต้องมี ไม่ว่าคุณจะเลือกแบบไหน (เส้นทาง ชื่อ ใบรับรอง คำขออนุญาตเครือข่ายท้องถิ่นของ iOS และไฟร์วอลล์): [การเข้าถึงจากนอก LAN ของคุณ](../server.md#reaching-it-from-outside-your-lan)
