# Cloudflare

สองวิธีในการวาง Cloudflare ไว้ระหว่างอุปกรณ์ของคุณกับเซิร์ฟเวอร์ของคุณ และการติดตั้งอ้างอิงใช้วิธีไหน ทั้งสองวิธีไม่ใช่ข้อบังคับ เซิร์ฟเวอร์ไม่รู้จักผู้ให้บริการรายใดตามชื่อ และ[การรันเซิร์ฟเวอร์](../server.md)ก็ไม่ต้องมีบัญชีกับใครทั้งสิ้น หน้านี้เหมาะกับคุณเมื่อต้องการเข้าถึงเซิร์ฟเวอร์จากนอกบ้านโดยไม่เปิดพอร์ตที่เราเตอร์ หรือเมื่อต้องการชื่อโฮสต์สาธารณะที่มีนโยบายการเข้าถึงกั้นอยู่ด้านหน้า

เมนูของ Cloudflare และเงื่อนไขของแพ็กเกจเปลี่ยนแปลงได้ ทุกขั้นตอนด้านล่างระบุเส้นทางเมนูตามที่เอกสารของ Cloudflare ระบุไว้ ณ วันที่ 2026-09-22 โปรดตรวจสอบหน้าปัจจุบันก่อนพึ่งพาขีดจำกัดหรือราคาใด ๆ

## เลือกแบบไหน

| แบบ | อุปกรณ์เห็นอะไร | อินเทอร์เน็ตเห็นอะไร | การซิงก์ครั้งแรกขนาดใหญ่ |
| --- | --- | --- | --- |
| **เส้นทางส่วนตัว** (การติดตั้งอ้างอิง) | ที่อยู่ส่วนตัวและชื่อของคุณเอง ผ่านไคลเอนต์ Cloudflare One | ไม่มีอะไรเลย: ไม่มีชื่อโฮสต์ ไม่มีพอร์ตเปิด | เป็นทราฟฟิกเครือข่ายส่วนตัว ไม่ผ่านชื่อโฮสต์สาธารณะ |
| **ชื่อโฮสต์สาธารณะพร้อม Access** | ชื่อสาธารณะ นโยบาย Access และโทเค็นบริการในปลั๊กอิน | ชื่อโฮสต์ที่อยู่หลัง Access | ผ่านพร็อกซีของ Cloudflare ภายใต้เงื่อนไขของผู้ให้บริการสำหรับไฟล์ขนาดใหญ่ |

เส้นทางส่วนตัวเป็นแบบอ้างอิง เพราะเซิร์ฟเวอร์ยังคงมองไม่เห็น และเพราะเอกสารของ Cloudflare เองก็ชี้ให้การถ่ายโอนขนาดใหญ่ไปทางนั้น: เส้นทางชื่อโฮสต์สาธารณะส่งทราฟฟิกผ่านพร็อกซีของ Cloudflare และในแพ็กเกจ Free, Pro และ Business เงื่อนไขเฉพาะบริการกำหนดให้ใช้บริการแบบเสียเงินสำหรับวิดีโอและไฟล์ขนาดใหญ่อื่น ๆ ขณะที่เส้นทางเครือข่ายส่วนตัวขนส่งไฟล์เหล่านั้นในฐานะทราฟฟิกของคุณเอง ไม่ว่าจะแบบใด ให้ทำการซิงก์ครั้งแรกขนาดใหญ่ใน LAN

สิ่งใดก็ตามที่สิ้นสุด TLS จะอ่านข้อมูลรับรองของคุณได้ แต่ไม่มีวันอ่านโน้ตของคุณได้: ทุกชิ้นข้อมูลและทุกรายการ manifest ถูกเข้ารหัสบนอุปกรณ์ และไม่มีกุญแจใดที่ถอดรหัสได้เดินทางผ่านสายเลย ([โมเดลภัยคุกคาม](../threat-model.md)) บนเส้นทางส่วนตัว จุดสิ้นสุด TLS เป็นของคุณเอง อยู่ภายในเครือข่ายของคุณ ส่วนชื่อโฮสต์สาธารณะ edge ก็เป็นจุดสิ้นสุด TLS อีกจุดหนึ่งด้วย

## แบบ A: เส้นทางส่วนตัวกับไคลเอนต์ Cloudflare One

เซิร์ฟเวอร์คงที่อยู่ส่วนตัวไว้ในเครือข่ายของคุณเอง มีตัวเชื่อมต่ออุโมงค์ทำงานอยู่ข้าง ๆ เส้นทางบอก Cloudflare ว่าที่อยู่ใดอยู่หลังอุโมงค์นั้น และไคลเอนต์ Cloudflare One (เดิมคือ WARP) บนอุปกรณ์แต่ละเครื่องนำทราฟฟิกไปยังที่อยู่เหล่านั้นผ่านอุโมงค์ URL ของเซิร์ฟเวอร์ที่อุปกรณ์ของคุณพิมพ์คือชื่อส่วนตัวที่แปลงเป็นที่อยู่ส่วนตัวนั้น

สิ่งที่ต้องมี: บัญชี Cloudflare ที่มีองค์กร Zero Trust ("ชื่อทีม") เครื่องหนึ่งในเครือข่ายของเซิร์ฟเวอร์ที่รันตัวเชื่อมต่ออุโมงค์ได้ และไคลเอนต์ Cloudflare One บนอุปกรณ์ทุกเครื่องที่จะซิงก์จากนอกบ้าน

1. **สร้างอุโมงค์** ในแดชบอร์ด Cloudflare ไปที่ **Networking** > **Tunnels** แล้วสร้างอุโมงค์ `cloudflared` รันตัวเชื่อมต่อที่ได้รับบนเครื่องภายในเครือข่ายของเซิร์ฟเวอร์: ในคลัสเตอร์ข้างเซิร์ฟเวอร์ หรือบนโฮสต์เดียวกัน
2. **กำหนดเส้นทางที่อยู่ส่วนตัวของเซิร์ฟเวอร์ผ่านอุโมงค์** ไปที่ **Networking** > **Routes** เลือก **Create route** > **Tunnel CIDR** เลือกอุโมงค์ แล้วกรอกที่อยู่ส่วนตัวหรือซับเน็ตของเซิร์ฟเวอร์ ที่อยู่เดียวก็พอ ซับเน็ตขยายได้ในภายหลัง
3. **ลงทะเบียนอุปกรณ์แต่ละเครื่อง** ติดตั้งไคลเอนต์ Cloudflare One กรอกชื่อทีม ทำการเข้าสู่ระบบที่องค์กรของคุณกำหนดให้ครบ แล้วเปิดการเชื่อมต่อ บน iOS และ Android ไคลเอนต์จะขอติดตั้งโปรไฟล์ VPN ให้ยอมรับ ตั้งค่าสิทธิ์การลงทะเบียนอุปกรณ์ให้มีเพียงตัวตนของคุณเองที่ลงทะเบียนได้
4. **ส่งช่วงที่อยู่ส่วนตัวผ่านไคลเอนต์** ในการตั้งค่า Split Tunnels ของไคลเอนต์ ตรวจให้แน่ใจว่าที่อยู่จากขั้นตอนที่ 2 ถูกกำหนดเส้นทางผ่านไคลเอนต์ ในโหมด **Exclude** ให้ลบบล็อก RFC 1918 ที่ครอบคลุมที่อยู่นั้น แล้วเพิ่มช่วงที่ยังต้องการยกเว้นกลับเข้าไป ในโหมด **Include** ให้เพิ่มที่อยู่หรือซับเน็ตนั้น
5. **ทำให้ชื่อแปลงได้บนอุปกรณ์** ปลั๊กอินส่งทุกคำขอไปยัง URL ของเซิร์ฟเวอร์ที่คุณพิมพ์ ดังนั้นชื่อนั้นต้องแปลงได้บนอุปกรณ์ที่อยู่นอกบ้าน: เส้นทางชื่อโฮสต์, Local Domain Fallback ไปยังตัวแปลงชื่อของคุณเอง หรือรายการ DNS ส่วนตัว ชื่อที่แปลงเป็นที่อยู่ซึ่งไคลเอนต์ไม่กำหนดเส้นทางจะล้มเหลวเหมือนกับเซิร์ฟเวอร์ที่ออฟไลน์ทุกประการ
6. **สิ้นสุด TLS ด้วยตัวเอง** เส้นทางนำทราฟฟิกของคุณไปยังจุดสิ้นสุด TLS ของคุณเอง: ingress หรือ reverse proxy ที่อยู่หน้าเซิร์ฟเวอร์พร้อมใบรับรองที่อุปกรณ์ทุกเครื่องเชื่อถือ เหมือนใน[การรันเซิร์ฟเวอร์](../server.md) เซิร์ฟเวอร์ทำงานด้วย `OBSYNC_EDGE=none` และเชื่อถือที่อยู่ที่ส่งต่อมาเฉพาะจาก `OBSYNC_TRUSTED_PROXY_CIDRS` ซึ่งเป็นช่วงที่อยู่ของจุดสิ้นสุด TLS เอง
7. **กรองด้วย Gateway หากต้องการ** นโยบายเครือข่ายของ Gateway สามารถอนุญาตให้เฉพาะอุปกรณ์ที่ลงทะเบียนของคุณเข้าถึงที่อยู่และพอร์ตของเซิร์ฟเวอร์ และบล็อกทุกอย่างอื่นบนเส้นทางนั้น
8. **ตรวจสอบจากอุปกรณ์ที่อยู่นอกเครือข่ายของคุณ** เปิด URL ของเซิร์ฟเวอร์ในเบราว์เซอร์บนอุปกรณ์นั้น แล้วควรเห็นหน้าเข้าสู่ระบบของแดชบอร์ด ในปลั๊กอิน เลือก **Check** ใต้ **Connection**: การไป-กลับครั้งเดียวพิสูจน์ที่อยู่ ใบรับรอง และข้อมูลรับรองพร้อมกัน

ข้อแลกเปลี่ยน:

- อุปกรณ์ทุกเครื่องที่ซิงก์ต้องรันไคลเอนต์ Cloudflare One และไคลเอนต์ต้องเชื่อมต่ออยู่ก่อนการซิงก์จากนอกบ้านจึงจะทำงาน
- Cloudflare ขนส่งทราฟฟิกระหว่างอุปกรณ์กับตัวเชื่อมต่ออุโมงค์ ปล่อยให้การถอดรหัส TLS ของ Gateway ปิดอยู่ ทราฟฟิกจะทึบสำหรับ Cloudflare นอกจากที่อยู่ ขนาด และเวลา ซึ่ง[โมเดลภัยคุกคาม](../threat-model.md)ยอมรับไว้อยู่แล้วสำหรับทุกเส้นทางเครือข่าย
- ตัวเชื่อมต่อคือโปรเซสในเครือข่ายของคุณที่รักษาการเชื่อมต่อขาออกไปยัง Cloudflare ไว้ตลอด เมื่อมันล่ม อุปกรณ์นอกบ้านจะแสดง `obsync: offline` ขณะที่ LAN ยังทำงานต่อไป

## แบบ B: ชื่อโฮสต์สาธารณะหลัง Access

เซิร์ฟเวอร์ได้ชื่อโฮสต์บนโดเมนที่คุณมีอยู่กับ Cloudflare อุโมงค์เผยแพร่ชื่อโฮสต์นั้นไปยังที่อยู่ส่วนตัวของเซิร์ฟเวอร์ และ Cloudflare Access กั้นอยู่ด้านหน้า: นโยบายตัวตนสำหรับแดชบอร์ด และโทเค็นบริการสำหรับการเรียก API ของปลั๊กอิน นี่คือแบบที่[การเชื่อมต่อแพลตฟอร์ม](../platform-onboarding.md)อธิบายไว้สำหรับคลัสเตอร์อ้างอิง และเป็นแบบที่การติดตั้งอ้างอิงยังไม่ได้เลือกใช้

1. **เผยแพร่ชื่อโฮสต์** ในการกำหนดค่าอุโมงค์ เพิ่มเส้นทางแอปพลิเคชันที่เผยแพร่จากชื่อโฮสต์ของคุณ (`sync.example.com` แทนชื่อของคุณเอง) ไปยังที่อยู่ HTTP ส่วนตัวของเซิร์ฟเวอร์ พอร์ต 8080 Cloudflare จะสร้างระเบียน DNS ให้
2. **วาง Access ไว้ด้านหน้า** ไปที่ **Zero Trust** > **Access controls** > **Applications** สร้างแอปพลิเคชัน **Self-hosted** บนชื่อโฮสต์นั้น แล้วเพิ่มนโยบายตัวตนที่อนุญาตเฉพาะคุณ เช่น PIN ใช้ครั้งเดียวที่ส่งไปยังที่อยู่ของคุณเอง สำหรับแดชบอร์ด
3. **สร้างโทเค็นบริการสำหรับปลั๊กอิน** ไปที่ **Zero Trust** > **Access controls** > **Service credentials** > **Service Tokens** สร้างหนึ่งรายการ แล้วคัดลอก Client ID และ Client Secret ค่า secret แสดงเพียงครั้งเดียว เพิ่มนโยบาย **Service Auth** ที่รวมโทเค็นนี้ให้กับแอปพลิเคชัน สำหรับเส้นทางที่ปลั๊กอินใช้ (`/v1/*`)
4. **วางโทเค็นลงในปลั๊กอิน** ใต้ **Edge service-token headers** บรรทัดละหนึ่งรายการ ตามชื่อที่ Cloudflare ใช้ทุกประการ:

   ```text
   CF-Access-Client-Id: <the client id>
   CF-Access-Client-Secret: <the client secret>
   ```

   ค่าเหล่านี้ไปพร้อมกับทุกคำขอที่ส่งไปยัง URL ของเซิร์ฟเวอร์ และไม่ไปที่อื่น
5. **บอกเซิร์ฟเวอร์ว่าอยู่หลัง edge** รันด้วย `OBSYNC_EDGE=cloudflare` ในโหมดนั้นทุกคำขอต้องมีส่วนหัวของ edge ที่ระบุที่อยู่ที่เชื่อมต่อและรหัสคำขอ และคำขอที่มาถึงโดยอ้อม edge จะถูกปฏิเสธด้วย `421 edge_required` ([การแก้ปัญหา](../troubleshooting.md#edge_required))
6. **ตรวจสอบ** เปิดชื่อโฮสต์ในเบราว์เซอร์ ควรเห็นหน้าเข้าสู่ระบบของ Access แล้วตามด้วยแดชบอร์ด ในปลั๊กอิน เลือก **Check** ใต้ **Connection**

ข้อแลกเปลี่ยน:

- ชื่อโฮสต์เป็นสาธารณะ Access ปฏิเสธคนแปลกหน้า และเซิร์ฟเวอร์ยังคงยืนยันตัวตนทุกคำขอของอุปกรณ์ด้วยตัวเอง แต่ชื่อนั้นมีอยู่จริงและถูกค้นพบได้
- โทเค็นบริการคือข้อมูลรับรอง ใครที่ถือมันไว้จะไปถึงประตูหน้าของ API ได้ การยืนยันตัวตนอุปกรณ์ของเซิร์ฟเวอร์เองยังคงกั้นอยู่ด้านหลัง หากรั่วไหลให้หมุนเวียนโทเค็นใน Cloudflare
- การถ่ายโอนขนาดใหญ่ผ่านพร็อกซีของ Cloudflare ภายใต้เงื่อนไขข้างต้น ให้ทำการซิงก์ครั้งแรกขนาดใหญ่ใน LAN
- ส่วนหัวของ edge ที่ระบุที่อยู่ที่เชื่อมต่อและประเทศ คือสิ่งที่หน้าอุปกรณ์ของแดชบอร์ดแสดงเป็นที่อยู่และประเทศในโหมดนี้

เส้นทางส่วนตัวคือเส้นทางของการติดตั้งอ้างอิง [การทดสอบเมื่อ 2026-09-14](../validation-runs/2026-09-14.md) บันทึกว่าวันนั้นไม่ได้ทดสอบเส้นทางนี้และเหตุผล ส่วน[การทดสอบเมื่อ 2026-09-20](../validation-runs/2026-09-20.md) บันทึกการทดสอบด้วยอุปกรณ์จริงบนเส้นทางอ้างอิง โดยการตรวจสอบการเชื่อมต่อและ TLS ผ่าน แบบชื่อโฮสต์สาธารณะยังไม่เคยถูกทดสอบในการทดสอบที่บันทึกไว้ครั้งใด
