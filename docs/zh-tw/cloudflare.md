# Cloudflare

在你的裝置與你的伺服器之間放置 Cloudflare 的兩種方式，以及參考部署採用的是哪一種。兩者都不是必要的：伺服器不認得任何服務商的名字，[執行伺服器](../server.md)也不需要在任何地方註冊帳號。如果你想在外出時不必在路由器上開放連接埠就能連到伺服器，或者想要一個前面設有存取政策的公開主機名稱，就看這一頁。

Cloudflare 的選單與方案條款會變動。下面每個步驟給出的選單路徑，都是 Cloudflare 文件在 2026-09-22 的寫法；在仰賴某個限額或價格之前，請核對最新頁面。

## 選哪一種

| 方式 | 裝置看到什麼 | 網際網路看到什麼 | 大量的首次同步 |
| --- | --- | --- | --- |
| **私有路由**（參考部署） | 透過 Cloudflare One 用戶端看到的你自己的私有位址與名稱 | 什麼都沒有：沒有主機名稱，沒有開放的連接埠 | 以私有網路流量傳輸，不經過公開主機名稱 |
| **搭配 Access 的公開主機名稱** | 一個公開名稱、一條 Access 政策、外掛程式裡的一組服務權杖 | Access 後方的主機名稱 | 經由 Cloudflare 代理，大型檔案受服務商條款約束 |

私有路由之所以是參考方式，一是伺服器始終不可見，二是 Cloudflare 自己的文件就把大量傳輸導向這條路：公開主機名稱路由把流量經 Cloudflare 代理，而在 Free、Pro 與 Business 方案下，服務專屬條款要求影片等大型檔案使用付費服務；私有網路路由則把它們當作你自己的流量傳輸。無論哪種方式，大量的首次同步都請在區域網路內完成。

無論由什麼終止 TLS，它都會讀到你的憑證，但永遠讀不到你的筆記：每個資料塊與每份清單都在裝置上加密，能解密它們的金鑰從不經過網路（[威脅模型](../threat-model.md)）。在私有路由上，終止點是你自己的，位於你的網路之內。在公開主機名稱方式下，邊緣節點也是一個終止點。

## 方式 A：私有路由與 Cloudflare One 用戶端

伺服器保留你自己網路中的私有位址。旁邊執行一個通道連接器，一條路由告訴 Cloudflare 哪些位址在這條通道後面，每台裝置上的 Cloudflare One 用戶端（原 WARP）把前往這些位址的流量送進通道。裝置裡填寫的伺服器 URL 是一個解析到該私有位址的私有名稱。

你需要：一個具備 Zero Trust 組織（「團隊名稱」）的 Cloudflare 帳號、伺服器網路內一台能執行通道連接器的機器，以及每台要在外出時同步的裝置上安裝的 Cloudflare One 用戶端。

1. **建立通道。** 在 Cloudflare 儀表板進入 **Networking** > **Tunnels**，建立一個 `cloudflared` 通道。把它提供的連接器執行在伺服器網路內的一台機器上：叢集裡伺服器的旁邊，或是同一台主機。
2. **把伺服器的私有位址路由進通道。** 進入 **Networking** > **Routes**，選擇 **Create route** > **Tunnel CIDR**，選取通道，填入伺服器的私有位址或子網路。一個位址就夠；子網路之後可以擴大。
3. **註冊每台裝置。** 安裝 Cloudflare One 用戶端，輸入團隊名稱，完成你的組織要求的登入，然後開啟連線。在 iOS 與 Android 上用戶端會要求安裝 VPN 描述檔，請允許。把裝置註冊權限設定為只有你自己的身分才能註冊。
4. **讓私有網段走用戶端。** 在用戶端的 Split Tunnels 設定裡，確認第 2 步的位址經由用戶端路由。在 **Exclude** 模式下，移除包含它的 RFC 1918 網段，再把仍想排除的網段加回去；在 **Include** 模式下，加入該位址或子網路。
5. **讓名稱在裝置上能解析。** 外掛程式把每個請求都送到你填寫的伺服器 URL，所以這個名稱必須在外出的裝置上能解析：一條主機名稱路由、指向你自己解析器的 Local Domain Fallback，或是一筆私有 DNS 記錄。解析到用戶端不路由的位址的名稱，會像離線伺服器一樣失敗。
6. **自己終止 TLS。** 路由把你的流量送到你自己的終止點：伺服器前方的 ingress 或反向代理，帶有每台裝置都信任的憑證，和[執行伺服器](../server.md)裡一樣。伺服器以 `OBSYNC_EDGE=none` 執行，只信任來自 `OBSYNC_TRUSTED_PROXY_CIDRS`（即終止點自身網段）的轉送位址。
7. **可選：用 Gateway 過濾。** 一條 Gateway 網路政策可以只允許你註冊過的裝置存取伺服器的位址與連接埠，並封鎖這條路由上的其他一切。
8. **從網路之外的裝置驗證。** 在那台裝置的瀏覽器裡開啟伺服器 URL，應該看到儀表板的登入頁。在外掛程式裡選擇 **Connection** 底下的 **Check**：一次往返同時證明位址、憑證與認證資料。

取捨：

- 每台同步的裝置都要執行 Cloudflare One 用戶端，用戶端連上之後外出同步才能運作。
- Cloudflare 承載裝置與通道連接器之間的流量。請讓 Gateway 的 TLS 解密保持關閉；這樣流量對它而言除了位址、大小與時間之外都是不透明的，而這些是[威脅模型](../threat-model.md)對任何網路路徑本來就承認的。
- 連接器是你網路裡的一個程序，持續維持一條到 Cloudflare 的對外連線。它一旦斷線，外出的裝置會顯示 `obsync: offline`，區域網路內則照常運作。

## 方式 B：Access 後方的公開主機名稱

伺服器取得一個你放在 Cloudflare 上的網域下的主機名稱。通道把這個主機名稱發布到伺服器的私有位址，前方站著 Cloudflare Access：儀表板用身分政策，外掛程式的 API 呼叫用服務權杖。這是[平台導入](../platform-onboarding.md)為參考叢集描述的方式，也是參考部署沒有採用的方式。

1. **發布主機名稱。** 在通道設定裡新增一條已發布應用程式路由，從你的主機名稱（`sync.example.com` 代表你自己的）指向伺服器的私有 HTTP 位址，連接埠 8080。DNS 記錄由 Cloudflare 建立。
2. **把 Access 放在前面。** 進入 **Zero Trust** > **Access controls** > **Applications**，在該主機名稱上建立一個 **Self-hosted** 應用程式，並為儀表板新增一條只允許你本人的身分政策，例如寄到你自己位址的一次性 PIN。
3. **為外掛程式建立服務權杖。** 進入 **Zero Trust** > **Access controls** > **Service credentials** > **Service Tokens**，建立一組，複製 Client ID 與 Client Secret；密鑰只會顯示一次。為外掛程式使用的路徑（`/v1/*`）替應用程式新增一條包含此權杖的 **Service Auth** 政策。
4. **把權杖貼到外掛程式裡。** 在 **Edge service-token headers** 底下按 Cloudflare 的命名逐行填寫：

   ```text
   CF-Access-Client-Id: <the client id>
   CF-Access-Client-Secret: <the client secret>
   ```

   它們隨每個送往伺服器 URL 的請求一起送出，不會送往別處。
5. **告訴伺服器它在邊緣節點後方。** 以 `OBSYNC_EDGE=cloudflare` 執行。在該模式下每個請求都必須帶有邊緣節點的連線位址與請求 ID 標頭，繞過邊緣節點抵達的請求會被以 `421 edge_required` 拒絕（[疑難排解](../troubleshooting.md#edge_required)）。
6. **驗證。** 在瀏覽器裡開啟主機名稱，應先看到 Access 登入，再看到儀表板。在外掛程式裡選擇 **Connection** 底下的 **Check**。

取捨：

- 主機名稱是公開的。Access 會拒絕陌生人，伺服器也仍然自行驗證每個裝置請求，但這個名稱存在，而且可以被發現。
- 服務權杖是一份認證資料。持有它的人能到達 API 的大門；伺服器自身的裝置驗證仍然守在後面。一旦外洩，請在 Cloudflare 裡輪替。
- 大量傳輸依上述條款經 Cloudflare 代理。大量的首次同步請在區域網路內完成。
- 在這種模式下，儀表板「裝置」頁顯示的位址與國家，就是邊緣節點的連線位址與國家標頭。
