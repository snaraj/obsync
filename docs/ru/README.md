# Self Hosted Private Sync

Самостоятельно размещаемая живая синхронизация со сквозным шифрованием для
[Obsidian](https://obsidian.md): один Rust-сервер без зависимостей со
встроенной панелью, который вы запускаете сами, плюс этот плагин. Файлы
любого размера, все платформы Obsidian, без подписки, без третьих сторон.

Установите его через Настройки → Сторонние плагины → Обзор под именем
**Self Hosted Private Sync** (идентификатор плагина `obsync-private-sync`),
на Obsidian 1.13.0 или новее.

> [!IMPORTANT]
> - Он синхронизируется с сервером, который запускаете **вы**: ни
>   размещённого сервиса, ни учётной записи где-либо ещё.
> - Сначала сделайте резервную копию хранилища; держите фразу восстановления
>   из 24 слов не на том устройстве, которое её создало.
> - Никогда не запускайте его рядом с другой синхронизацией (Obsidian Sync,
>   облачная папка, другой плагин) на одном хранилище.
> - Молодая программа: прочитайте запись [`CHANGELOG.md`](../../CHANGELOG.md)
>   о вашей версии, обновляйте каждое устройство и знайте, что охватил каждый
>   [прогон проверки](../validation-runs/).

## К чему этот плагин получает доступ

- **Ваш сервер и ничего больше.** Каждый запрос идёт на **Server URL**,
  который вы вводите; ни телеметрии, ни третьих сторон.
- **Учётная запись на этом сервере**, созданная из токена первичной
  настройки; ваша учётная запись Obsidian здесь ни при чём.
- **GitHub Releases, через Obsidian**, для установки и обновления;
  дополнительные файлы релиза Obsidian игнорирует.
- **Список файлов вашего хранилища**, чтобы решить, что синхронизировать;
  скрытые (`.obsidian`, `.git`) и папки-симлинки пропускаются.
- **Буфер обмена: только запись** кнопками **Copy code** и **Copy link** в
  **Pair a new device**, никогда не чтение.

Что сервер может видеть, а что нет: [`SECURITY.md`](../../SECURITY.md) и
[модель угроз](../threat-model.md).

## Начать синхронизацию

Пять шагов от пустоты до двух синхронных устройств. `v1.0.6` — релиз, для
которого написана эта страница; берите тег того релиза, который
устанавливаете вы.

### 1. Запустите сервер

Проверьте подпись, а затем запустите ровно тот дайджест, который она
напечатала:

```sh
cosign verify ghcr.io/snaraj/obsync:v1.0.6 \
  --certificate-identity https://github.com/snaraj/obsync/.github/workflows/release-publisher.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Самый простой путь — Compose с Caddy из локальной копии этого репозитория:
HTTPS в любой сети, без домена и без учётной записи у кого бы то ни было.

```sh
OBSYNC_IMAGE=ghcr.io/snaraj/obsync@sha256:<digest> \
  OBSYNC_HOST=sync.example.org \
  OBSYNC_BIND_ADDRESS=192.168.1.10 \
  docker compose -f deploy/compose/docker-compose.yml up -d
```

`OBSYNC_HOST` — имя, которое будут вводить ваши устройства; оно должно
разрешаться только в вашей собственной сети. `OBSYNC_BIND_ADDRESS` — адрес,
на котором публикуются порты 80 и 443: адрес привязки ограничивает интерфейс
назначения, а не источник, поэтому решает ваш межсетевой экран, кто до него
дотянется. Compose отказывается стартовать, пока вы не выберете.

Уже есть HTTPS перед сервером — от прокси или туннеля, которому вы доверяете?
Тогда запустите вместо этого голый сервер:
[Запуск сервера](../server.md).

### 2. Прочитайте токен первичной настройки

При первом запуске сервер выпускает токен первичной настройки и записывает
его на свой том журнала, с режимом 0600, никогда не попадая в логи. Токен
один раз создаёт вашу учётную запись и остаётся входом в панель для
восстановления доступа: берегите его так же, как фразу восстановления.
Читайте его прямо из контейнера:

```sh
docker cp obsync-obsync-1:/data/journal/v1/setup-token - | tar -xO
```

### 3. Доверьтесь сертификату, один раз на устройство

Caddy подписывает сертификатом удостоверяющего центра, который создал при
первом запуске, поэтому каждому устройству нужно один раз ему довериться.
Экспортируйте корневой сертификат и установите его на каждой платформе так,
как показывает
[Запуск сервера](../server.md#trust-the-certificate-authority-once-per-device);
на iOS доверие сертификату — это второй переключатель после его установки.

### 4. Настройте первое устройство

1. Настройки → Сторонние плагины → Обзор → **Self Hosted Private Sync** →
   Установить → Включить.
2. Укажите в **Server URL** ваш сервер (`https://sync.example.org`, вместе с
   портом, если он не 443), затем выберите **Whole vault** или
   **Selected folders only**; позже выбор может только сужаться.

   ![Вкладка настроек плагина: поле Server URL с демонстрационным именем хоста, поле заголовков периметра и строка Connection с кнопками Check и Open dashboard](../assets/settings-server.png)

3. Вставьте токен первичной настройки в **First-time setup**, выберите
   **Set up** и запишите фразу восстановления из 24 слов.

   ![Раздел This device вкладки настроек: строка Pairing с Pair this device и Pair a new device, строка First-time setup с полем Setup token и кнопкой Set up, а также строка Vault key](../assets/settings-setup.png)

### 5. Сопрягите второе устройство

1. Установите там плагин с тем же **Server URL**; на первом устройстве
   запустите **Pair a new device** и получите код, действительный десять
   минут.

   ![Диалог Pair a new device на первом устройстве, его код скрыт, с кнопками Copy code и Copy link и строкой Waiting for the new device](../assets/pair-new-device.png)

2. На втором устройстве откройте **Pair this device**, вставьте код и
   выберите **Pair**.
3. Вернувшись на первое устройство, подтвердите его по имени.
   Отредактируйте заметку на любом из них; она появится на другом за
   считаные секунды.

   ![Первое устройство спрашивает, подтвердить ли новое устройство по имени, с кнопками Approve и Reject](../assets/pair-approve.png)

![Анимация: код сопряжения показан на первом устройстве, вставлен на втором, подтверждён на первом, и первая заметка приходит на второе](../assets/pairing.gif)

Пробуете на одном компьютере? На компьютере `http://127.0.0.1:8080`
дотягивается до голого сервера; Obsidian на iOS и Android отказывается от
обычного HTTP.

Снимков экрана с телефонов в этом репозитории пока нет; они делаются на
собственных устройствах сопровождающего и добавляются, когда их зафиксирует
прогон проверки.

Каждый шаг полностью: [Быстрый старт](../quickstart.md).

## Для продвинутых: Cloudflare

У эталонной установки нет публичного имени хоста: Cloudflare Tunnel и
приватный маршрут дотягиваются до сети сервера, а клиент Cloudflare One на
каждом устройстве переносит туда URL сервера. Публичное имя хоста за
Cloudflare Access — с сервисным токеном в **Edge service-token headers** и
`OBSYNC_EDGE=cloudflare` — тоже работает. Оба варианта, шаг за шагом:
[Cloudflare](cloudflare.md).

## Другие способы добраться до вашего сервера

Что бы вы ни выбрали, плагину нужен HTTPS с сертификатом, которому доверяет
каждое устройство; сам сервер остаётся на обычном HTTP за этим терминатором.

- **Только локальная сеть.** Путь Compose выше, доступный только дома; вне
  дома синхронизации нет.
- **WireGuard.** Ваш собственный VPN домой: самое быстрое и целиком ваше;
  конфигурация пира на каждом устройстве.
- **Tailscale.** Управляемая mesh-сеть WireGuard: меньше всего настройки;
  координирует её третья сторона, на условиях своего тарифа.
- **Обратный прокси с автоматическим TLS**, например Caddy на публичном
  имени: доступен из интернета, обновлять его вам.
- **Cloudflare Tunnel.** См. выше. Никакого входящего порта; провайдер на
  пути, на своих условиях.

Что нужно устройству в пути (маршрут, имя, сертификат, межсетевой экран,
запрос iOS о локальной сети):
[Доступ извне вашей локальной сети](../server.md#reaching-it-from-outside-your-lan).

## Устранение неполадок

| Симптом | Вероятная причина | Что попробовать первым |
| --- | --- | --- |
| `obsync: offline` | Устройство не дотягивается до URL сервера | Откройте этот URL в браузере на том же устройстве; проверьте порт, HTTPS, маршрут |
| Телефон не подключается, пока компьютер синхронизируется | Телефон не доверяет приватному сертификату | Установите корневой сертификат; на iOS дополнительно включите его в разделе «Доверие сертификатам» |
| `401 stale_timestamp` | Часы расходятся более чем на 300 секунд | Включите автоматическое время на устройстве или на сервере |
| `403 device_pending` | Устройство пока никто не подтвердил | Подтвердите его по имени на том устройстве, с которого сопрягали |
| Файл так и не приходит | Он вне выбранных папок или выше предела размера для телефона | Проверьте **Sync folders on this device**; на телефоне запустите **Show remote-only files** |

Любой другой симптом и код ошибки, а также как сообщить о нём:
[Устранение неполадок](../troubleshooting.md).
