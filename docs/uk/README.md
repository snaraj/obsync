# Self Hosted Private Sync

Самостійно розміщена, наскрізно зашифрована жива синхронізація для
[Obsidian](https://obsidian.md): один сервер на Rust без залежностей із
вбудованою панеллю, який ви запускаєте самі, плюс цей плагін. Файли будь-якого
розміру, кожна платформа Obsidian, без підписки, без третьої сторони.

Встановіть його в Налаштування → Сторонні додатки → Огляд як **Self Hosted
Private Sync** (ID плагіна `obsync-private-sync`), на Obsidian 1.13.0 або
новішій.

> [!IMPORTANT]
> - Він синхронізується із сервером, який запускаєте **ви**: без розміщеного сервісу, без облікового запису деінде.
> - Спершу зробіть резервну копію сховища; тримайте 24-слівну фразу відновлення не на тому пристрої, який її створив.
> - Ніколи не запускайте його поруч з іншою синхронізацією (Obsidian Sync, хмарна тека, інший плагін) на одному сховищі.
> - Молоде програмне забезпечення: прочитайте запис [`CHANGELOG.md`](../../CHANGELOG.md) про вашу версію, оновіть кожен пристрій і знайте, що охопив кожен [прогін перевірки](../validation-runs/).

## До чого має доступ цей плагін

- **Ваш сервер і більше нічого.** Кожен запит іде на **Server URL**, який ви вводите; без телеметрії, без третьої сторони.
- **Обліковий запис на цьому сервері**, створений із токена початкового налаштування; ваш обліковий запис Obsidian тут ні до чого.
- **GitHub Releases, через Obsidian**, для встановлення та оновлення; додаткові файли релізу Obsidian ігнорує.
- **Список файлів вашого сховища**, щоб вирішити, що синхронізувати; приховані (`.obsidian`, `.git`) теки та теки-символьні посилання пропускаються.
- **Буфер обміну, лише для запису** кнопками **Copy code** і **Copy link** у **Pair a new device**, ніколи для читання.

Що сервер може і чого не може бачити: [`SECURITY.md`](../../SECURITY.md) і
[модель загроз](../threat-model.md).

## Почати синхронізацію

П'ять кроків від нуля до двох синхронізованих пристроїв. `v1.0.6` — це реліз,
для якого писалася ця сторінка; беріть тег того релізу, який встановлюєте ви.

### 1. Запустіть сервер

Перевірте підпис, а потім запустіть саме той дайджест, який він надрукував:

```sh
cosign verify ghcr.io/snaraj/obsync:v1.0.6 \
  --certificate-identity https://github.com/snaraj/obsync/.github/workflows/release-publisher.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Найпростіший шлях — Compose з Caddy, із локальної копії цього репозиторію:
HTTPS у будь-якій мережі, без домену, без облікового запису будь-де.

```sh
OBSYNC_IMAGE=ghcr.io/snaraj/obsync@sha256:<digest> \
  OBSYNC_HOST=sync.example.org \
  OBSYNC_BIND_ADDRESS=192.168.1.10 \
  docker compose -f deploy/compose/docker-compose.yml up -d
```

`OBSYNC_HOST` — це ім'я, яке вводитимуть ваші пристрої; воно має
розв'язуватися лише у вашій власній мережі. `OBSYNC_BIND_ADDRESS` — це адреса,
на якій публікуються порти 80 і 443: адреса прив'язки обмежує інтерфейс
призначення, а не джерело, тож хто до нього дістанеться, вирішує ваш
брандмауер. Compose відмовляється стартувати, доки ви не вибрали.

Уже маєте HTTPS попереду, від проксі чи тунелю, якому ви довіряєте? Тоді
запустіть натомість голий сервер: [Запуск сервера](../server.md).

### 2. Прочитайте токен початкового налаштування

При першому запуску сервер карбує токен початкового налаштування й записує
його на свій том журналу, режим 0600, ніколи не логуючи. Він один раз створює
ваш обліковий запис і лишається входом відновлення для панелі: бережіть його
так само, як фразу відновлення. Читайте його з контейнера:

```sh
docker cp obsync-obsync-1:/data/journal/v1/setup-token - | tar -xO
```

### 3. Довіртеся сертифікату, один раз на пристрій

Caddy підписує сертифікатом центру, який він створив при першому старті; кожен
пристрій має один раз йому довіритися. Експортуйте кореневий сертифікат і
встановіть його на кожній платформі так, як показує
[Запуск сервера](../server.md#trust-the-certificate-authority-once-per-device);
на iOS довіра до нього — це другий перемикач після встановлення.

### 4. Налаштуйте перший пристрій

1. Налаштування → Сторонні додатки → Огляд → **Self Hosted Private Sync** →
   Встановити → Увімкнути.
2. Встановіть **Server URL** на ваш сервер (`https://sync.example.org`, з
   портом, якщо він не 443), потім виберіть **Whole vault** або **Selected
   folders only**; пізніше вибір може лише звужуватися.

   ![Вкладка налаштувань плагіна: поле Server URL із демонстраційним іменем хоста, поле заголовків краю та рядок Connection з кнопками Check і Open dashboard](../assets/settings-server.png)

3. Вставте токен початкового налаштування під **First-time setup**, виберіть
   **Set up** і запишіть 24-слівну фразу відновлення.

   ![Розділ This device вкладки налаштувань: рядок Pairing із Pair this device та Pair a new device, рядок First-time setup із полем Setup token і кнопкою Set up, а також рядок Vault key](../assets/settings-setup.png)

### 5. Поєднайте другий пристрій

1. Встановіть там плагін із тим самим **Server URL**; на першому пристрої
   запустіть **Pair a new device**, щоб дістати код, дійсний десять хвилин.

   ![Діалог Pair a new device на першому пристрої, його код приховано, з кнопками Copy code і Copy link та рядком Waiting for the new device](../assets/pair-new-device.png)

2. На другому пристрої відкрийте **Pair this device**, вставте код і виберіть
   **Pair**.
3. Знову на першому пристрої схваліть його за іменем. Відредагуйте нотатку на
   будь-якому з них; вона з'явиться на іншому за кілька секунд.

   ![Перший пристрій питає, чи схвалити новий пристрій за іменем, з кнопками Approve і Reject](../assets/pair-approve.png)

![Анімація: код поєднання показано на першому пристрої, вставлено на другому, схвалено на першому, і перша нотатка прибуває на другий](../assets/pairing.gif)

Пробуєте на одному комп'ютері? `http://127.0.0.1:8080` дістається голого
сервера на комп'ютері; Obsidian на iOS та Android відмовляє простому HTTP.

Знімків екрана з телефона в цьому репозиторії ще немає; їх роблять на власних
пристроях супровідника й додають, коли їх зафіксує прогін перевірки.

Кожен крок у повній довжині: [Швидкий старт](../quickstart.md).

## Для досвідчених: Cloudflare

Еталонне розгортання не має публічного імені хоста: Cloudflare Tunnel і
приватний маршрут дістаються мережі сервера, а клієнт Cloudflare One на
кожному пристрої несе туди Server URL. Публічне ім'я хоста за Cloudflare
Access, із сервісним токеном у **Edge service-token headers** і
`OBSYNC_EDGE=cloudflare`, теж працює. Обидва, крок за кроком:
[Cloudflare](cloudflare.md).

## Інші способи дістатися вашого сервера

Що б ви не вибрали, плагіну потрібен HTTPS із сертифікатом, якому довіряє
кожен пристрій, а сам сервер лишається на простому HTTP за цим термінатором.

- **Лише LAN.** Шлях Compose вище, досяжний тільки вдома; без синхронізації поза домом.
- **WireGuard.** Ваш власний VPN назад у вашу мережу: найшвидше й цілком ваше; конфігурація учасника на кожному пристрої.
- **Tailscale.** Керована мережа WireGuard: найменше налаштування; координує її третя сторона, на умовах свого тарифу.
- **Зворотний проксі з автоматичним TLS**, наприклад Caddy на публічному імені: досяжний з інтернету, оновлювати його вам.
- **Cloudflare Tunnel.** Вище. Без вхідного порту; провайдер на шляху, на своїх умовах.

Що потрібно пристрою в дорозі (маршрут, ім'я, сертифікат, брандмауер, запит
iOS про локальну мережу):
[Доступ ззовні вашої LAN](../server.md#reaching-it-from-outside-your-lan).

## Усунення несправностей

| Симптом | Імовірна причина | Що спробувати першим |
| --- | --- | --- |
| `obsync: offline` | Пристрій не дістається до Server URL | Відкрийте URL у браузері на тому самому пристрої; перевірте порт, HTTPS і маршрут |
| Телефон не під'єднується, поки комп'ютер синхронізується | Приватному сертифікату на телефоні не довіряють | Встановіть кореневий сертифікат; на iOS додатково увімкніть його в «Certificate Trust Settings» |
| `401 stale_timestamp` | Годинник розходиться більш ніж на 300 секунд | Увімкніть автоматичний час, на пристрої або на сервері |
| `403 device_pending` | Ніхто ще не схвалив пристрій | Схваліть його за іменем на пристрої, з якого ви поєднували |
| Файл так і не прибуває | Він поза вибором тек або перевищує стелю розміру для телефона | Перевірте **Sync folders on this device**; на телефоні запустіть **Show remote-only files** |

Будь-який інший симптом і код помилки, і як про нього повідомити:
[Усунення несправностей](../troubleshooting.md).
