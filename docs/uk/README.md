# Self Hosted Private Sync

Самостійно розміщена, наскрізно зашифрована жива синхронізація для
[Obsidian](https://obsidian.md). Ваші нотатки синхронізуються через сервер,
який ви запускаєте самі. Нотатки, вкладення та імена файлів шифруються на
вашому пристрої, і сервер ніколи не отримує ключ. Плагін працює на кожній
платформі, де працює Obsidian, на комп'ютері й на телефоні. Немає ні
підписки, ні облікового запису деінде.

**Щось не працює? → [Усунення несправностей](https://snaraj.github.io/obsync/troubleshooting/) (англійською)**

## Установлення

![Налаштування плагіна відкриваються розділом Get started: рядок Setup guide з кнопкою Open the guide, над полем Server URL](../assets/settings-get-started.png)

Установіть плагін через **Налаштування → Сторонні додатки → Огляд**. Знайдіть
**Self Hosted Private Sync** (ID плагіна `obsync-private-sync`). Потрібен
Obsidian 1.13.0 або новіший. Налаштування плагіна відкриваються посібником з
налаштування: до нього одне натискання.

> [!IMPORTANT]
> - Він синхронізується із сервером, який запускаєте **ви**: без розміщеного сервісу, без облікового запису деінде.
> - Спершу зробіть резервну копію сховища; тримайте 24-слівну фразу відновлення не на тому пристрої, який її створив.
> - Ніколи не запускайте його поруч з іншою синхронізацією (Obsidian Sync, хмарна тека, інший плагін) на одному сховищі.
> - Молоде програмне забезпечення: прочитайте запис [`CHANGELOG.md`](../../CHANGELOG.md) про вашу версію, оновіть кожен пристрій і знайте, що охопив кожен [прогін перевірки](../validation-runs/).

## Почати синхронізацію

Найкоротший повний шлях — Compose із Caddy у вашій власній мережі, з клону
цього репозиторію. Він дає HTTPS у будь-якій мережі, без домену й без
облікового запису будь-де. [Одна мережа, крок за кроком](../same-network.md)
проводить ним із кожним екраном. Замініть `vX.Y.Z` нижче на випуск, який
установлюєте, — найновіший тег на
[сторінці Releases](https://github.com/snaraj/obsync/releases/latest).

**1. Перевірте образ.** Потім запускайте саме той дайджест, який вивела
перевірка:

```sh
cosign verify ghcr.io/snaraj/obsync:vX.Y.Z \
  --certificate-identity https://github.com/snaraj/obsync/.github/workflows/release-publisher.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

**2. Запустіть сервер:**

```sh
OBSYNC_IMAGE=ghcr.io/snaraj/obsync@sha256:<digest> \
  OBSYNC_HOST=sync.example.org \
  OBSYNC_BIND_ADDRESS=192.168.1.10 \
  docker compose -f deploy/compose/docker-compose.yml up -d
```

`OBSYNC_HOST` — це ім'я, яке вводитимуть ваші пристрої. Воно має
розв'язуватися лише у вашій власній мережі. `OBSYNC_BIND_ADDRESS` — адреса, на
якій публікуються порти 80 і 443: адреса прив'язки обмежує інтерфейс
призначення, а не джерело, тож хто до неї дістанеться, вирішує ваш брандмауер.
Compose не запуститься, доки ви не зробите вибір.

**3. Прочитайте токен початкового налаштування.** Під час першого запуску
сервер випускає токен початкового налаштування й записує його у свій том
журналу, з режимом 0600, і ніколи не пише його в логи. Він один раз створює ваш
обліковий запис і лишається резервним способом входу до панелі. Бережіть його
так само, як фразу відновлення:

```sh
docker cp obsync-obsync-1:/data/journal/v1/setup-token - | tar -xO
```

**4. Налаштуйте кожен пристрій.** Один раз довіртеся сертифікату сервера
([як](../server.md#trust-the-certificate-authority-once-per-device)).
Установіть плагін і дотримуйтеся [Швидкого старту](../quickstart.md):
налаштуйте перший пристрій, потім під'єднайте решту.

Перед сервером уже стоїть HTTPS від проксі чи тунелю, якому ви довіряєте?
Тоді запустіть [голий сервер](../server.md#already-have-a-tls-terminator-docker).

## До чого має доступ цей плагін

- **Ваш сервер і більше нічого.** Кожен запит іде на **Server URL**, який ви вводите; без телеметрії, без третьої сторони.
- **Обліковий запис на цьому сервері**, створений із токена початкового налаштування; ваш обліковий запис Obsidian тут ні до чого.
- **GitHub Releases, через Obsidian**, для встановлення та оновлення; додаткові файли випуску Obsidian ігнорує.
- **Список файлів вашого сховища**, щоб вирішити, що синхронізувати; приховані теки (`.obsidian`, `.git`) і теки-символьні посилання пропускаються.
- **Буфер обміну, лише для запису** кнопками **Copy code** і **Copy link** у **Pair a new device**, ніколи для читання.
- **Ваш браузер, коли ви просите посібник з налаштування.** Посібник проєкту відкривається в ньому; сам плагін нічого не надсилає.

Що сервер може і чого не може бачити: [`SECURITY.md`](../../SECURITY.md) і [модель загроз](../threat-model.md).

## Версії

LATEST — це найновіший тег на
[сторінці Releases](https://github.com/snaraj/obsync/releases/latest). Саме
його Obsidian установлює й до нього оновлюється. `main` — це EDGE: злита, але
ще не випущена робота, для тих, хто збирає з вихідного коду. Бета-каналу й
попередніх тегів немає. Розділ Unreleased у журналі змін — це запис того, що
є в EDGE.
