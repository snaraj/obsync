# Documentation-site build inputs, pinned by exact version AND by the sha256 of
# the exact wheel each line installs.
#
# WHY A FILE OF ITS OWN. AGENTS.md requirement 5 keeps the product
# dependency-free: the Rust workspace is the standard library, the plugin has
# no runtime dependency, and the dashboard is hand-written. MkDocs is not a
# product input. It is CI TOOLING, like cosign, helm and gitleaks, it ships
# nothing into the binary, the chart or the plugin bundle, and every page it
# renders is a Markdown file a reader can open in this repository without it.
# Requirement 5 also says CI tooling is pinned "by version AND checksum", which
# is why every line below carries its `--hash`.
#
# THE INSTALL COMMAND, and what each flag buys:
#
#     python3 -m pip install --require-hashes --no-deps --only-binary=:all: \
#       -r docs/requirements.txt
#
# `--require-hashes` binds the BYTES: pip refuses the install unless every
# downloaded wheel matches a hash written here, and it refuses a requirement
# that carries none, so a line added without one fails closed rather than
# silently widening the closure. `--no-deps` means pip installs exactly these
# lines and resolves nothing, so a new release of a dependency of a dependency
# cannot enter a build. `--only-binary=:all:` refuses source distributions, so
# no package's own build code runs here. Adding, removing or moving a line is a
# reviewed edit, and a version bump is a new hash read off the new wheel.
#
# ONE PLATFORM, DELIBERATELY. A wheel's sha256 is a fact about one file, and a
# package with compiled parts publishes a different file per interpreter and
# platform. These are the wheels for CPython 3.12 on linux/amd64 -- the
# interpreter `.github/workflows/docs-site.yml` pins and the platform its
# runner is -- so `--require-hashes` here means "the bytes CI installs", not
# "some build of this version". Building the site on another interpreter or
# another platform therefore goes through the same container CI's runner is
# close to, which `docs/index.md` gives as the one build command; a venv on a
# developer's own Python is not the reproduction and is not claimed to be.
#
# Resolved and hashed 2026-09-20 in `python:3.12-slim` on `linux/amd64` with
# `pip download --no-deps --only-binary=:all: -r docs/requirements.txt` followed
# by `pip hash` over every downloaded wheel.
